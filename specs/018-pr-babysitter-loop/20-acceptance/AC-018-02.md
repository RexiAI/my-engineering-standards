# AC-018-02: watcher enumerates open PRs and records check status with the absent/unknown distinction

## AC-018-02-01 — The loop discovers open PRs with the real mechanism
Given a loop run starts
When the watcher enumerates PRs
Then it lists open PRs via `gh pr list --state open` or the GitHub MCP `github_list_pull_requests`
And each open PR is recorded in the watchlist exactly once per run

## AC-018-02-02 — The loop records full triage state per PR
Given a watched PR
When the triage skill runs against it
Then the loop records in `STATE.md` the check status per check (passing/failing/pending/absent-unknown)
And whether the required-check policy is known
And review state (approvals, unresolved threads)
And mergeability
And the resulting ready-to-merge verdict

## AC-018-02-03 — Zero returned checks is absent/unknown, never green
Given a PR whose checks return no reports
Or a PR whose required-check policy read failed
When the triage verdict is computed
Then the PR is recorded as absent-unknown / policy unknown
And the PR is not ready to merge

## AC-018-02-04 — Any non-passing required check blocks readiness
Given a PR with a required check that is pending
Or failing
Or absent-unknown
When the triage verdict is computed
Then the PR is not ready to merge

## AC-018-02-05 — Spec-pipeline draft PRs are not fought
Given a PR on a `spec/NNN-slug` branch that is a draft
When the loop triages it
Then the loop records its state only
And it does not propose fixes for CI failures
And it does not add labels
And it does not comment on the pipeline's own failures
And once green and undrafted it may ping the human
