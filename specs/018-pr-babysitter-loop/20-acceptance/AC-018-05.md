# AC-018-05: remediation is bounded per PR; repeated failures escalate; human gates guard high-risk changes

## AC-018-05-01 — Circuit breaker caps fix attempts per PR
Given a watched PR with a failing check
When fix attempts reach 3 without progress
And "no progress" means no new commits from the author between attempts or the same check failing at the same head SHA
Then the loop escalates to the human with the failing check and last attempt evidence
And it stops commenting on that PR

## AC-018-05-02 — Repeated failures escalate instead of repeating comments
Given a PR whose same failing check recurs across runs
When the loop would comment on it again
Then it escalates to the human instead
And it does not post the same comment a second time

## AC-018-05-03 — Human gate for high-risk changes
Given a PR that is a high-risk refactor
Or touches security, auth, payments, or infra per the 016 `gate.yaml` path denylist
Or touches more than 10 files
When the loop would spawn a fix sub-agent
Then it escalates to the human for a decision instead
And no fix proposal is made without that decision

## AC-018-05-04 — Idle PRs get a single close/hand-off suggestion
Given a watched PR with no commits and no loop or human action for more than 3 days
When the loop triages it
Then it posts one suggestion to close or hand off
And it records the suggestion in state
And it does not re-ping on later runs
