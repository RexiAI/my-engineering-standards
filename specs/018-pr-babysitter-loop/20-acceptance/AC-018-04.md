# AC-018-04: ready PRs get a label or a human ping; ambiguity escalates

## AC-018-04-01 — Ready verdict adds the "ready to merge" label or pings the human
Given a PR whose triage verdict is ready
When the loop acts
Then it adds the `"ready to merge"` label via `gh pr edit <n> --add-label "ready to merge"`
And if label creation fails it pings the human with a comment instead

## AC-018-04-02 — No label on any non-ready verdict
Given a PR that is not ready to merge
Because its policy is unknown
Or any required check is absent-unknown, failing, or pending
Or approval is missing
Or discussion threads are unresolved
Or it has a merge conflict
Or it is a draft
When the loop acts
Then it does not add the "ready to merge" label
And it does not ping the human with a ready notice

## AC-018-04-03 — Ambiguous or high-risk items escalate with context
Given a PR whose triage is ambiguous
Or a PR that trips a human gate
When the loop acts
Then it escalates to the human with the PR link and what is uncertain
And it does not add the "ready to merge" label
