# AC-018-01: pr-review-triage skill exists and defines review norms, required-check policy, and ready-to-merge

## AC-018-01-01 — The triage skill file exists with valid frontmatter
Given the repo root
And spec 016's skill layout (`skills/<name>/SKILL.md`)
When the triage skill is delivered
Then `skills/pr-review-triage/SKILL.md` exists
And its YAML frontmatter declares `name: pr-review-triage`
And its `allowed-tools` restrict the loop to read/comment operations

## AC-018-01-02 — The skill defines the repo's review norms
Given `docs/GIT_WORKFLOW.md §PR Requirements`
When the triage skill is read
Then it states PR titles follow conventional-commit format
And it states at least one reviewer approval is required at `production`+ tier (`mvp` may self-approve)
And it states no unresolved discussion threads are allowed
And it states merge is squash-only

## AC-018-01-03 — The skill defines the required-check policy source of truth
Given GitHub branch protection and this repo's `.github/workflows/`
When the triage skill is read
Then it names branch protection `required_status_checks.contexts` on the default branch as the policy source
And it names `.github/workflows/*.yml` as the cross-check for what CI actually runs
And it states the policy is "known" only when both reads succeed, otherwise "unknown"

## AC-018-01-04 — The skill defines "ready to merge"
Given a triaged PR
When its readiness is evaluated
Then "ready to merge" requires policy known and all required checks passing
And at least the tier-required approval present
And no unresolved discussion threads
And no merge conflict
And the PR is not a draft

## AC-018-01-05 — The skill defines the check-state taxonomy
Given a set of check-run reports for a PR
When each check is classified
Then every check is one of passing, failing, pending, or absent-unknown
And zero returned checks is classified absent-unknown
And absent-unknown is never treated as green
