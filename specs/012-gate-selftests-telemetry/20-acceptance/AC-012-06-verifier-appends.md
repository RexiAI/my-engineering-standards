# AC-012-06: the Verifier appends one record per completed run

## AC-012-06-01 — spec-verifier.md documents the telemetry step (AC-003)
Given `agents/spec-verifier.md` is the Verifier's instruction file
When the telemetry task completes
Then `agents/spec-verifier.md` instructs the Verifier to append exactly one record to `runs.jsonl` via `scripts/record-gate-run.sh` after its checks complete
And it maps the record fields to its own run: `gatesFailed` = checks that FAILed or BLOCKed, `warnings` = WARN findings, `durationSec` = wall-clock verification time, `outcome` = block/fail/pass per precedence, `specSlug` from the `specs/NNN-slug` directory under verification
And it states `runId` is generated by the script

## AC-012-06-02 — The append goes through record-gate-run.sh, no new edit permission
Given the Verifier's `permission.edit` allows only `specs/*/25-verification.md` and `permission.bash` allows all commands
When the Verifier records the run
Then it invokes `scripts/record-gate-run.sh` via bash (the sanctioned path)
And no `permission.edit` change is required for the append to work

## AC-012-06-03 — A record is appended even on FAIL or BLOCK verdicts
Given the Verifier's checks produced a FAIL (or BLOCK) verdict
When the run completes
Then a record with `outcome` set to `fail` (or `block`) is appended
And a failed verification still records, rather than silently skipping telemetry

## AC-012-06-04 — Outcome precedence is block over fail over pass
Given a run where one gate BLOCKed and another FAILed
When the record is composed
Then `outcome` is `block`
Given a run with only WARN findings
When the record is composed
Then `outcome` is `pass`

## AC-012-06-05 — spec-pipeline.md exports loop/retry context to the record
Given `agents/spec-pipeline.md` is the orchestrator's instruction file
When it delegates to the Verifier during `/build`
Then it exports `SPEC_LOOP_COUNT`, `SPEC_PHASE1_RETRIES`, and `SPEC_PHASE2_RETRIES` from its loop/retry tracking (spec 008 budgets) so `record-gate-run.sh` fills those fields
And when it has no tracked counts it exports nothing, and the record defaults those fields to 0
