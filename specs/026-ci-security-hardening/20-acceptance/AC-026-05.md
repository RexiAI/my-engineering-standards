# AC-026-05: production SSH host key is pinned, never disabled

## AC-026-05 — `StrictHostKeyChecking=no` is gone; `SSH_KNOWN_HOSTS` pins the host key

Given the `ci-deploy-ssh.yml` reusable workflow is called with an optional
`SSH_KNOWN_HOSTS` secret (host key output of `ssh-keyscan`, captured
out-of-band)
When the `deploy` job runs
Then an "Establish known_hosts" step writes that secret to
  `~/.ssh/known_hosts` when present (or falls back to a one-time
  `ssh-keyscan`, with an explicit `::warning::` naming the residual TOFU
  gap, when absent)
And every subsequent `ssh`/`scp` invocation uses
  `-o StrictHostKeyChecking=yes`
And no step in the file uses `StrictHostKeyChecking=no`.

Checkable by reading code:
- `.github/workflows/ci-deploy-ssh.yml` declares an `SSH_KNOWN_HOSTS` secret.
- `grep -c StrictHostKeyChecking=no .github/workflows/ci-deploy-ssh.yml`
  returns 0.
- Every `ssh`/`scp` invocation in the file passes
  `-o StrictHostKeyChecking=yes` (or `-p`/`-P` port then that option).
