# AC-026-06: deploy-workflow caller inputs are validated before remote use

## AC-026-06 — `app-dir` / `service-name` are rejected if they contain unsafe characters

Given a child repo calls `ci-deploy-ssh.yml` with
  `inputs.app-dir: "foo; rm -rf /"` (or any value outside
  `[A-Za-z0-9._/-]`)
When the `deploy` job runs
Then a "Validate caller-supplied inputs" step rejects the value and the job
  fails (`exit 1`) before any `ssh`/`scp` command is constructed with it.

Given a child repo calls it with a normal value (e.g. `/opt/my-service`)
When the same step runs
Then validation passes and the job proceeds normally.

Checkable by reading code:
- `.github/workflows/ci-deploy-ssh.yml` contains a step that matches
  `inputs.service-name` and `inputs.app-dir` against
  `^[A-Za-z0-9._/-]*$` and exits non-zero on a mismatch, running before
  "Copy compose + nginx config to host" and "Deploy service with Docker
  Compose".
