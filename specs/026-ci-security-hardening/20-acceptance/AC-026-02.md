# AC-026-02: PR-review agent's permission block loads for real in CI

## AC-026-02 — `--agent pr-review` invocation, not frontmatter-stripped prompt concatenation

Given `agents/pr-review.md` declares `mode: primary` and a `permission`
block denying all edits and allow-listing only read-only `bash` commands
When `.github/workflows/ci-pr-review.yml`'s review step runs
Then it invokes `/tmp/opencode-bin/opencode run --agent pr-review "<prompt>"`
And the prompt carries only trusted, workflow-supplied values (PR number,
  head SHA) — never a `cat agents/pr-review.md | sed ...` concatenation
And the agent's real `permission` block is loaded by opencode at that
  invocation, so `edit: deny` and the bash allow-list are enforced by
  config, not by prose the agent could choose to ignore.

Checkable by reading code:
- `agents/pr-review.md` frontmatter contains `mode: primary`.
- `.github/workflows/ci-pr-review.yml`'s review step contains
  `--agent pr-review` and does not contain `sed '/^---$/,/^---$/d'`.
- `scripts/check-pr-review.sh` asserts `mode: primary` (not `mode: subagent`)
  for AC-024-01-01, and passes end to end.
