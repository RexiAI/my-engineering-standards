# AC-026-13: every third-party Action and cross-repo workflow reference is SHA-pinned

## AC-026-13 — no `.github/workflows/*.yml` uses a mutable ref for a third-party Action or a cross-repo `workflow_call`

Given every `uses:` line in `.github/workflows/*.yml` that references a
third-party Action (`actions/*`, `docker/*`, `github/*`,
`aquasecurity/*`, `dependabot/*`, `cycjimmy/*`, `peter-evans/*`,
`ruby/*`) or this repo's own reusable workflows from another repo context
(`RexiAI/my-engineering-standards/.github/workflows/*.yml`)
When the workflow files are inspected
Then each such `uses:` targets a full 40-character commit SHA (with a
  trailing `# vX.Y.Z` or `# pinned; ...` comment for humans), never a
  branch (`@main`, `@master`) or a floating major-version tag (`@v4`).

Given `scripts/init-ci.sh` generates a child repo's `ci.yml`
When it emits a `uses: RexiAI/my-engineering-standards/.github/workflows/...`
  line for any of `--with-release`, `--with-deploy`, `--with-pr-review`, or
  a language/frontend CI job
Then every one of those lines uses the same `STANDARDS_PIN` commit-SHA
  constant, never `@main`.

Checkable by reading code and by running the script:
- `grep -rE 'uses: (actions|docker|github|aquasecurity|dependabot|cycjimmy|peter-evans|ruby)/[^@]+@(v[0-9]|master)' .github/workflows/*.yml`
  returns no matches.
- `grep -r 'my-engineering-standards/.github/workflows/[^@]*@main' .github .`
  returns no matches outside a documentation example that itself shows the
  SHA-pinned form as the recommended pattern.
- Running `scripts/init-ci.sh --with-pr-review --with-release --platform
  github --backend go` in a scratch repo produces a `ci.yml` with no
  `@main` reference.
