# AC-026-11: remote-sourced toolchain versions validated before sed -i

## AC-026-11 — an unexpected version shape is rejected, not written into a manifest or a sed program

Given the Go/Node/Python "check for newer toolchain version" steps in
`ci-toolchain-bump.yml` fetch a `latest` value from an external endpoint
(go.dev, nodejs.org, or the actions/python-versions manifest)
When that value does not match the expected shape (`N.N` or `N.N.N` for Go,
`N` for Node, `N.N.N` for Python)
Then the step emits a `::warning::` naming the unexpected value and its
  source, sets `changed=false`, and exits before any `sed -i` or file-write
  touches `go.mod` / `.nvmrc` / `.python-version`.

Given the fetched value matches the expected shape and differs from the
current pinned version
When the same step runs
Then it proceeds to update the manifest as before.

Checkable by reading code:
- Each of the three steps in `.github/workflows/ci-toolchain-bump.yml`
  contains a `[[ "$latest" =~ ^...$ ]]` shape check that runs before its
  `sed -i` / `echo > <manifest>` line, with an `::warning::` on mismatch.
