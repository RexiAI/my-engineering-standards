# AC-026-01: ci-sweeper.yml is closed against the pwn-request pattern

## AC-026-01 — Fork-originated Self CI failures never reach the privileged sweep; same-repo failures still get swept via a trusted checkout

Given a fork's pull request makes the `Self CI` workflow fail on this repo,
and the fork's commit also modifies `scripts/install-opencode.sh`
When the `ci-sweeper.yml` `workflow_run` job evaluates its `if:` condition
Then the job does not run, because
  `github.event.workflow_run.head_repository.full_name != github.repository`,
  and no step ever installs or executes anything from that commit.

Given instead a Self CI run on this repo's own `main` branch fails
When `ci-sweeper.yml`'s `sweep` job runs
Then `actions/checkout` runs with no `ref:` override (the workflow's own
  trusted ref, never `github.event.workflow_run.head_sha`), and the
  ci-triage skill inspects the failure only via `gh run view --log-failed`
  (a read-only API call), never the checked-out tree of the failing commit.

Checkable by reading code:
- `.github/workflows/ci-sweeper.yml`'s `sweep` job `if:` includes
  `github.event.workflow_run.head_repository.full_name == github.repository`.
- The `actions/checkout` step in that job has no `ref:` key.
- `skills/ci-triage/SKILL.md` instructs `gh run view <RUN-ID> --log-failed`
  and nowhere instructs reading the checked-out tree for the failure.
