# AC-026-09: hardcoded-secrets gate no longer exempts quoted literals

## AC-026-09 — a quoted, real-looking secret is caught; every legitimate placeholder form still passes; scan scope widened

Given a file under a scanned directory contains
  `API_SECRET="<a real-looking literal value>"`
When `scripts/check-no-hardcoded-secrets.sh` scans that directory
Then it is reported as a violation (exit 1) — quoting alone no longer
  exempts the value from the secret-style-assignment check.

Given a file contains a variable reference (`FOO="$HOME/.ssh/id_rsa"`,
`FOO="${BAR}"`), an angle-bracket placeholder
(`GH_TOKEN="<your-github-personal-access-token>"`), or a recognized
placeholder/example word (`YOUR_*`, `PLACEHOLDER`, `example`, `changeme`,
`xxx`, `dummy`, `sample`), quoted or not
When the same script scans that directory
Then it passes clean (exit 0) — none of these forms are flagged.

Given the same content appears under `.github/`, `config/`, `templates/`,
or `ci/` (previously outside the scanned scope)
When the script runs with no path argument (repo root)
Then it is scanned and, if a real secret, caught.

Checkable by reading code and by running the script:
- `scripts/check-no-hardcoded-secrets.sh`'s `is_ignored_rhs` no longer
  contains an unconditional `'"'* | "'"*` early-return case.
- `bash scripts/check-no-hardcoded-secrets.sh --self-test` exits 0 and
  reports all four cases (quoted real secret caught, quoted angle-bracket
  placeholder passes, unquoted `YOUR_*` passes, literal token prefix caught
  under the widened `.github/` scope) as PASS.
- `bash scripts/check-no-hardcoded-secrets.sh` (no args, real repo tree)
  exits 0.
