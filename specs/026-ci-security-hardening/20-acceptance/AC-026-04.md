# AC-026-04: opencode binary download is checksum-verified

## AC-026-04 — install-opencode.sh verifies SHA-256 before executing; daily-triage.yml stops duplicating the download

Given `scripts/install-opencode.sh` pins `VERSION` and a `SHA256` for the
release tarball
When the script downloads the tarball
Then it runs `sha256sum -c` against the pinned checksum before extracting,
  and aborts (via `set -euo pipefail`) if the checksum does not match.

Given `.github/workflows/daily-triage.yml` previously duplicated the
download logic inline with no checksum
When the workflow installs opencode
Then it calls `bash scripts/install-opencode.sh` instead, inheriting the
  checksum verification and the single source of truth for the pinned
  version.

Checkable by reading code:
- `scripts/install-opencode.sh` contains `SHA256=` and a `sha256sum -c` call
  before the `tar -xzf` line.
- `.github/workflows/daily-triage.yml`'s "Install opencode" step is
  `run: bash scripts/install-opencode.sh` and no longer contains its own
  `curl`/`tar` lines.
