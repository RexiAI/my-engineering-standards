# AC-030-04 — Agent e2e-runner

## AC-030-04-01 — Frontmatter has required fields
Given the file `agents/e2e-runner.md` exists
When the frontmatter is parsed
Then `description` field is present and non-empty
And `mode` field is present with value `subagent`
And `permission` block is present

## AC-030-04-02 — Permission denies git push and git commit
Given the frontmatter `permission.bash` block
When its entries are examined
Then a deny rule for `git push*` exists
And a deny rule for `git commit*` exists

## AC-030-04-03 — Permission denies edits outside allowed paths
Given the frontmatter `permission.edit` block
When its entries are examined
Then edits are denied outside `tests/`, `e2e.config.ts`, and `.e2e/`
And `.e2e/` is read-only (not writable)

## AC-030-04-04 — No model key in frontmatter
Given the frontmatter
When its fields are listed
Then no `model` key is present

## AC-030-04-05 — Body has required sections
Given the file body (after frontmatter)
When section headings or structural markers are searched
Then a Role/Purpose section exists
And a "one rule" or primary invariant section exists
And execution steps for author/maintainer duty exist
And execution steps for bug-bash mode duty exist
And stopping conditions are defined
And an output summary contract is defined

## AC-030-04-06 — Workflow vs Agent choice justified
Given the file body
When searched for justification
Then a statement explaining why an agent (not a workflow) is appropriate exists

## AC-030-04-07 — Ground truth and stopping conditions
Given the file body
When searched for ground-truth requirements
Then a requirement to read `.e2e/failures/` and `report.json` after every run exists
And a statement that the agent must never assume green without checking output exists
Given the file body
When searched for stopping conditions
Then a max of 3 fix rounds per failing test file is stated
And framework budgets are stated as the inner bound
And the phrase "re-run until green" is stated as forbidden
And every re-run is described as a counted attempt

## AC-030-04-08 — Bug-bash mode bounds and confirmation gate
Given the file body's bug-bash mode section
When searched for bounds
Then a persona count cap is stated
And per-persona `--max-steps` and `--timeout` bounds are stated
And the ASSERTION_FAILED confirmation gate is stated (only repro tests failing with ASSERTION_FAILED count as bugs)
And a statement that explore findings are not regressions exists
Given the entire file
When searched for literal model/provider ids and secrets
Then no literal model or provider ids are found
And no secrets, tokens, or credentials are found
And no "re-run until green" phrasing exists as an instruction (only as forbidden)
