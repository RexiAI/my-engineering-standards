# AC-029: Live E2E verification

## AC-029-70 — E2E runs when local server available
Given `JUDGMENT_BACKEND=local`
And the local server is running and healthy
When the E2E verification is executed
Then at least one ci-triage-style question is sent through `scripts/typed-judgment.sh`
And at least one spec-ux-style question is sent through `scripts/typed-judgment.sh`
And the spike report addendum records: answer, confidence, latency_ms, usage tokens per question

## AC-029-71 — E2E compares against LLM fallback
Given the E2E verification ran successfully
When the spike report addendum is read
Then at least one real case's local-backend answer is compared against the LLM fallback path's answer
And agreement or disagreement is recorded (advisory, not a gate)

## AC-029-72 — E2E skipped with reason when server unavailable
Given the local server is not available (no GPU in CI, or target machine not accessible)
When the E2E verification is attempted
Then the spike report addendum contains a skip-with-reason entry
And the reason is stated (e.g. "CI has no GPU", "target machine not accessible")

## AC-029-73 — E2E uses telemetry format from spec 028
Given the E2E verification ran
When the spike report addendum is read
Then each recorded question uses the run-log telemetry format from spec 028: question shape, backend, answer, confidence, latency_ms, usage, timestamp

## AC-029-74 — Consumers unchanged
Given the spec 029 changes are applied
When `skills/ci-triage/SKILL.md` and `agents/spec-ux.md` are diffed against their spec-028 versions
Then the diff is empty — zero changes to consumer files
