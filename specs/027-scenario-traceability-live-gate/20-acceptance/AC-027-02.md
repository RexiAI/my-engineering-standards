# AC-027-02: live scenario-traceability check wired into self-ci

## AC-027-02 — self-ci runs the real check against the live tree, not just its hermetic selftest

Given `.github/workflows/self-ci.yml`'s `validate` job previously ran only
`scripts/check-scenario-traceability.selftest.sh` (isolated `mktemp -d`
fixtures — never this repo's own `specs/` + source tree)
When the workflow file is inspected
Then a step running `bash scripts/check-scenario-traceability.sh` (no
  arguments, no `continue-on-error`) exists alongside the existing selftest
  step.

Given a future spec PR introduces an untraced scenario or a stale reference
within its own in-flight `specs/NNN-*/` folder
When self-ci's `validate` job runs on that PR
Then this new step catches it and fails the job (AC-027-01's scoping
  ensures no other spec's archived citations produce false-positive noise).

Given no `specs/` folder exists (the normal state of `main` between spec
PRs)
When this step runs
Then it exits 0 (`finish_clean`) — a no-op, never a failure.

Checkable by reading code:
- `.github/workflows/self-ci.yml`'s `validate` job contains
  `run: bash scripts/check-scenario-traceability.sh` with no positional
  arguments and no `continue-on-error: true`, positioned after "Run gate
  selftests".
